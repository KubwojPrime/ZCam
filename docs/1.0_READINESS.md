# ZCam 1.0 Readiness

This document tracks the formal gate for promoting ZCam from the `0.x` line to
`1.0`.

## Release Positioning

`1.0` should mean:

- The app can be installed and used by a non-developer on a trusted LAN/VPN.
- Default setup does not expose predictable credentials.
- The release APK is signed with a production key.
- The local security model is documented and tested.
- The privacy model is explicit.
- Recovery behavior is bounded and observable.
- Core runtime flows have been tested for long-running operation.

## P0 Blockers

- Decide and document whether `isMinifyEnabled` remains false or should be
  enabled for release.
- Replace developer defaults `PIN = 0000` and `apiToken = local-token` with
  either generated per-install credentials or a mandatory first-run setup flow.
- Review `android:usesCleartextTraffic="true"` and keep it only with a clear
  LAN-only threat model and endpoint authorization tests.
- Run a complete security pass over all HTTP and WebSocket endpoints.
- Add an in-app legal/about screen exposing the AGPL license, source access,
  warranty disclaimer, attribution notice, and third-party notices.
- Add project-wide SPDX headers or an equivalent automated license-header
  policy before accepting external contributions.
- Run a 24-hour stability test with camera preview, recording, audio, network
  reconnect, and device thermal pressure.
- Verify storage retention under low-space conditions on a physical device.
- Verify boot restore behavior on a physical device.
- Verify app behavior after process death and app data corruption scenarios.
- Produce final user-facing privacy and permission wording.

## P1 Before 1.0

- Add release notes template.
- Add screenshots or short usage guide for server/client pairing.
- Add a troubleshooting guide for networking, permissions, and recordings.
- Add an installation guide for APK sideloading.
- Add a contributor-facing license confirmation for external contributions.
- Add endpoint regression tests for auth-denied and auth-success cases.
- Add a manual QA checklist for target Android versions.
- Add a migration note for users upgrading from `0.x`.
- Decide whether the local fallback web panel is part of the supported 1.0
  surface or an emergency/debug surface.

## P2 Nice To Have

- Add SBOM or dependency inventory.
- Add dependency license summary and third-party notices.
- Add structured release artifacts beyond APK, such as checksum files.
- Add reproducible release build notes.
- Add in-app "About" page with version, license, attribution, privacy, and
  support links.

## Current Known Formal Risks

- The app still carries developer default credentials.
- The manifest allows cleartext traffic because local HTTP is part of the
  runtime design.
- Release minification is disabled.
- APKs are produced manually and uploaded to GitHub Releases manually.
- The AGPL/source-offer/legal notice flow is documented but not yet surfaced
  inside the app UI.
- Store metadata and legal/privacy review are not complete.

## Suggested 1.0 Release Checklist

1. Close all P0 blockers.
2. Update `CHANGELOG.md`.
3. Update `README.md` current release status.
4. Bump `versionCode` and `versionName` to `1.0.0`.
5. Run `.\gradlew.bat test`.
6. Run `.\gradlew.bat :app:assembleRelease`.
7. Verify APK signing certificate.
8. Install APK on a clean physical device.
9. Complete server mode smoke test.
10. Complete client mode pairing smoke test.
11. Complete recording and playback smoke test.
12. Complete network reconnect smoke test.
13. Generate SHA256 checksum.
14. Commit source changes.
15. Push `main`.
16. Create GitHub Release `v1.0.0`.
17. Upload APK and checksum.
18. Verify GitHub asset digest.
